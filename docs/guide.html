Guide

Written front to back. Every snippet assumes using namespace Tweeny; at the top of the file, and compiles against the package as it ships.

Your first tween

A tween is created by calling a function that says what to animate, where it should end up and how long it should take. It starts playing immediately and cleans itself up when it finishes.

angelscript 
using namespace Tweeny;

class Door : CometBehaviour
{
    void Start()
    {
        // Slide two units to the right over half a second.
        Move(Transform::Get(entity), Vector2(2.0f, 0.0f), 0.5f);
    }
}

That is the whole thing. There is no manager to add, no update call to write and nothing to dispose of. The package registers its runner through a project setting, so it exists the moment the package is in the project.

Anatomy of a tween

Creating a tween returns it, and every setting on it returns the tween again, so an animation reads as one statement. The shape is always the same: a shortcut, then settings, then callbacks.

angelscript 
Move(transform, target, 1.0f)      // what, where, how long
    .SetEase(Ease::OutBack)        // how it accelerates
    .SetLoops(-1, LoopType::Yoyo)  // how often, and in which direction
    .SetDelay(0.25f)               // when it starts
    .SetId("door")                 // how to find it later
    .OnComplete(TweenCallback(this.OnDoorOpen));

Shortcuts take their target as the first argument. AngelScript has no extension methods, so a shortcut is a free function in the Tweeny namespace rather than a method on the object: Move(transform, ...), not transform.Move(...).

Position is authoritative

Internally a tween never accumulates. Each frame it works out the absolute position on its timeline and jumps there, which is why seeking, rewinding and sequence playback all land on exactly the same values as playing forward normally.

Project defaults

Project Settings › TweenySettings holds the defaults every new tween starts from: easing curve and its overshoot and period, loop type, auto-kill, auto-play, whether tweens are recycled at scene load, the global time scale and the log level. Setting something on a tween overrides the default for that tween only.

Easing

Easing is the difference between something sliding and something arriving. Tweeny ships thirty-eight curves. In starts slow, Out ends slow, InOut does both; Back overshoots, Elastic springs, Bounce settles, Flash blinks.

Choosing a curve

angelscript 
// A named curve.
Move(transform, target, 1.0f).SetEase(Ease::OutBounce);

// Back and Elastic take extra shape parameters.
Move(transform, target, 1.0f).SetEase(Ease::OutBack, 3.0f);
Move(transform, target, 1.0f).SetEase(Ease::OutElastic, 1.5f, 0.4f);

// Your own function, of type EaseFunc.
Move(transform, target, 1.0f).SetEase(EaseFunc(this.MyCurve));

// Any curve, sampled in eight discrete steps.
Move(transform, target, 1.0f)
    .SetEase(EaseFactory::StopMotion(8, Ease::Linear));

A custom curve is any function matching EaseFunc: it receives elapsed time, duration, and the overshoot and period parameters, and returns the eased fraction.

Loops and direction

SetLoops(count) repeats a tween. A count of -1 runs forever. The LoopType decides what a repeat means:

Loop typeWhat each cycle does
LoopType::RestartSnaps back to the start value and plays forward again.
LoopType::YoyoPlays backwards, then forwards, alternating.
LoopType::IncrementalAdds the change again, so each cycle travels further than the last.

Setting a loop

angelscript 
MoveX(transform, 5.0f, 1.0f).SetLoops(-1, LoopType::Yoyo);
MoveX(transform, 5.0f, 1.0f).SetLoops(4, LoopType::Incremental);
MoveX(transform, 5.0f, 1.0f).SetLoops(-1, LoopType::Restart);

// Reverse a running tween in place.
ITween@ t = MoveX(transform, 5.0f, 1.0f);
t.Flip();

Delay, relative and speed-based

Three settings change what the duration and the destination mean.

angelscript 
// Wait a quarter of a second before starting.
Move(transform, target, 1.0f).SetDelay(0.25f);

// The destination is an offset from wherever the value starts,
// not an absolute position.
MoveX(transform, 3.0f, 1.0f).SetRelative(true);

// The third argument stops being a duration and becomes a speed,
// in units per second. Travel time follows from the distance.
MoveX(transform, 20.0f, 4.0f).SetSpeedBased(true);

// Round the animated value to whole numbers as it goes.
MoveX(transform, 10.0f, 1.0f).SetSnapping(true);

Starting somewhere else

From turns a tween around: the value you gave becomes the start, and whatever the target already held becomes the end. It is how entrances are written — fade in from transparent, drop in from above — without having to set the starting state by hand first.

angelscript 
// Slide in from three units above, ending where the object already is.
Move(transform, Vector2(0.0f, 3.0f), 0.5f).From(true);

// Fade in from fully transparent.
Fade(renderer, 1.0f, 0.4f).From(0.0f);

// Set up the from value without snapping to it immediately.
Fade(renderer, 1.0f, 0.4f).From(0.0f, false);

Callbacks

Eight lifecycle callbacks, each taking a TweenCallback. They fire in a fixed order, so OnStepComplete always precedes the OnComplete of the final loop.

CallbackWhen it fires
OnStartOnce, the first time the tween actually updates — after any delay.
OnPlayEvery time it starts or resumes playing.
OnPauseEvery time it is paused.
OnRewindEvery time it is rewound to the beginning.
OnUpdateEvery frame the value changes.
OnStepCompleteAt the end of each loop cycle.
OnCompleteOnce, when every loop has finished.
OnKillOnce, when the tween is destroyed, however that happens.
angelscript 
Move(transform, target, 2.0f)
    .OnStart(TweenCallback(this.OnDoorStarts))
    .OnStepComplete(TweenCallback(this.OnDoorStep))
    .OnComplete(TweenCallback(this.OnDoorOpen));

void OnDoorOpen() { Debug::Log("open"); }

Playback control

Every tween can be played, paused, rewound, restarted, completed, flipped and seeked. Keep the handle to drive it, and turn auto-kill off if you want it to survive past its own completion.

Driving a tween by hand

angelscript 
TweenVector3@ t = Move(transform, target, 2.0f).SetAutoKill(false);

t.Pause();
t.Play();
t.TogglePause();
t.PlayBackwards();
t.Rewind();               // back to the start, delay included
t.SmoothRewind();         // rewind from wherever it is, easing out
t.Restart();
t.Flip();                 // swap start and end, mid-flight
t.Goto(1.0f, true);       // jump to one second in and keep playing
t.Complete(false);        // snap to the end; true also fires callbacks
t.Kill(false);            // stop and release; true completes it first

The same tween also reports on itself: IsPlaying, IsComplete, IsBackwards, GetPosition, GetElapsed, GetCompletedLoops, GetFullDuration and more.

Finding tweens again

You do not have to keep handles. Tag a tween with an id, or look it up by the object it animates, and drive whole groups at once. Every one of these returns how many tweens it touched.

angelscript 
MoveX(transform, 5.0f, 1.0f).SetId("intro");

Pause("intro");
Kill("intro");
Kill(transform);            // everything animating this object
Restart(transform);

bool busy = IsTweening(transform);
int  live = TotalActiveTweens();

PauseAll();
KillAll(true);              // true completes them first
SetTimeScale(0.25f);        // slow motion for every tween at once

Sequences

A sequence is a timeline you assemble from tweens, intervals and callbacks. It behaves like a tween itself: it eases, loops, takes callbacks, and can be paused or seeked as one thing — and sequences nest inside sequences.

BuilderWhere it puts the tween
AppendAfter everything added so far.
JoinAlongside the last thing appended, starting at the same moment.
PrependBefore everything else, pushing the rest later.
InsertAt an exact time on the timeline.
AppendIntervalEmpty time, to space things out.
AppendCallbackA function call at that point on the timeline.

Building a sequence

angelscript 
TweenSequence@ intro = Sequence();

intro.Append(Move(transform, Vector2(0.0f, 3.0f), 0.5f));
intro.Join(Tint(renderer, Color(1, 0.3f, 0.3f, 1), 0.5f));  // with the move
intro.AppendInterval(0.2f);
intro.Append(Scale(transform, 1.5f, 0.3f));
intro.Insert(0.0f, Fade(renderer, 1.0f, 1.0f));             // at t = 0
intro.AppendCallback(TweenCallback(this.OnIntroDone));

intro.SetLoops(2, LoopType::Restart)
   .SetEase(Ease::InOutSine);

Two things at once

To animate two properties of the same object together you do not need a sequence at all. Tweens are independent, so two of them on one target simply run side by side.

angelscript 
// Grows and reddens at the same time, no sequence involved.
Scale(transform, 1.5f, 0.4f);
Tint(renderer, Color(1, 0.2f, 0.2f, 1), 0.4f);

Reach for a sequence when the timing has to be related — one thing after another, a shared pause, or the whole group treated as a single animation you can rewind.

Punch, shake and jump

Impact effects. Punch and shake both return exactly to where they started, so they can be fired on top of whatever else is happening without leaving anything displaced. A shake accepts a seed, so the same shake can be replayed identically — useful in tests and in replays.

Firing an impact

angelscript 
// A directed hit that oscillates back to rest.
PunchPosition(transform, Vector2(0.5f, 0.0f), 0.4f);
PunchScale(transform, Vector2(0.3f, 0.3f), 0.4f, 10, 1.0f);

// Random shaking, optionally reproducible.
ShakePosition(transform, 0.5f, 2.0f, 14);
ShakePosition(transform, 0.5f, 2.0f, 14, 90.0f, true, 4242);
ShakeCamera(cameraTransform, 0.4f, 0.6f);

// An arc to a destination, in two hops.
Jump(transform, Vector2(8.0f, 0.0f), 3.0f, 2, 1.0f);

Jump returns a TweenSequence, because that is what it is: a horizontal move with a series of vertical arcs joined onto it. Everything you can do to a sequence works on it.

Paths

A path moves something through a list of waypoints, either in straight lines or along a smooth curve. The path is measured when the tween starts, so travel happens at a constant speed instead of racing through wherever the waypoints happen to bunch up.

Walking a route

angelscript 
array<Vector2> route = { Vector2(5, 3), Vector2(5, -1), Vector2(-5, -1) };

Path(transform, route, 4.0f, PathType::Linear)
    .SetClosePath(true);

Path(transform, route, 4.0f, PathType::CatmullRom)
    .OnWaypointChange(TweenCallbackInt(this.OnWaypoint));

void OnWaypoint(int index) { Debug::Log("reached " + index); }

Shortcuts

Shortcuts are the ready-made tweens for things the engine already has. They cover the transform, every renderer, tilemaps, the camera, lights, audio and the whole UI stack. The reference lists all of them; these are the ones you will reach for daily.

The everyday shortcuts

angelscript 
Move(transform, Vector2(3.0f, 1.0f), 1.0f);
MoveX(transform, 3.0f, 1.0f);
LocalMove(transform, Vector2(0.0f, 2.0f), 1.0f);
Scale(transform, 1.5f, 0.4f);
ScaleY(transform, 2.0f, 0.4f);
Rotate(transform, 360.0f, 1.0f);

Tint(renderer, Color(1, 0.4f, 0.2f, 1), 0.5f);
Fade(renderer, 0.0f, 0.5f);
Why Tint and not Color

Color is already a CometEngine type. A function of the same name would make every file that imports both namespaces ambiguous, so the colour shortcut is called Tint.

Rotation is a single angle in degrees rather than a quaternion, because CometEngine is a 2D engine — and because an angle can express something a rotation cannot. RotateMode::FastBeyond360 turns two and a half times; a quaternion only knows where you finish.

Your own values

Anything you can read and write can be tweened. Hand To a getter and a setter and it will animate a value Tweeny has never heard of — a health bar, a shader parameter, a difficulty curve.

angelscript 
class HealthBar : CometBehaviour
{
    private float health = 20.0f;

    private float GetHealth() { return health; }
    private void SetHealth(float value) { health = value; }

    void Heal()
    {
        To(FloatGetter(this.GetHealth), FloatSetter(this.SetHealth), 100.0f, 2.0f)
            .SetEase(Ease::OutQuint);
    }
}

There is a To for every value type the package supports — float, int, Vector2, Vector3, Color, Rectf and string — plus ToAlpha for just the alpha channel of a colour and ToAngle for a rotation. This is also the extension point: a shortcut Tweeny does not ship is a To you write once.

Text and numbers

Integer tweens round as they go, so a score counts in whole numbers. String tweens type text out, and can fill the untyped remainder with scrambled characters.

angelscript 
To(IntGetter(this.GetScore), IntSetter(this.SetScore), 1500, 1.5f);

To(StringGetter(this.GetLabel), StringSetter(this.SetLabel), "READY", 1.0f)
    .SetScramble(ScrambleMode::Uppercase);

Coroutines

Six yield instructions turn a coroutine into a readable script for a cutscene. A tween that gets killed releases whatever is waiting on it, so a coroutine can never be stranded by an animation that went away.

Waiting on a tween

angelscript 
void PlayIntro()
{
  Yield(WaitForCompletion(Move(transform, up, 0.6f).SetEase(Ease::OutBack)));
  Yield(WaitForSeconds(0.2f));
  Yield(WaitForCompletion(Tint(renderer, gold, 0.4f)));
  Yield(WaitForElapsedLoops(spinner, 3));
  Yield(WaitForPosition(runner, 1.5f));
}

Linking to an entity

A tween that outlives what it animates is the most common way tween code goes wrong: the target is destroyed and the tween keeps writing into nothing. Link it to an entity and it follows that entity's fate.

angelscript 
ITween@ t = Move(transform, target, 5.0f);
SetLink(t, entity, LinkBehaviour::PauseOnDisablePlayOnEnable);
Destruction always kills

Whichever behaviour you choose, a destroyed entity kills the tween. A link that only pauses on disable would otherwise leak the moment the entity is gone.

No code at all

Add a TweenyAnimation component to an entity, choose what to animate and how, and press Play. It covers moves, scales, rotations, tints, fades, punches and shakes, with the same easing, delay and looping options as the scripting API — and it can start on its own or be triggered from code.

Editor tools

Tweeny › Tweeny Inspector in the main menu opens a window listing every live tween with its id, target, progress and state, and gives each one play, pause, rewind, complete and kill buttons.

The same window previews animations without entering play mode. It records the state of every target before it starts and puts all of it back when you stop, so previewing never leaves a scene dirty.

Lifetime and cleanup

By default a tween kills itself when it completes, and you never think about it again. Turn that off with SetAutoKill(false) when you want to replay or rewind the same tween later — and remember that such a tween now lives until you kill it.

There is no object pool. Pools exist to dodge a tracing garbage collector; AngelScript is reference counted, so a finished tween is released the moment the last handle drops. A pool would buy nothing here and would bring its worst failure mode: a recycled tween that reports itself alive while being a completely different animation.

Update loops and time scale

Tweens run on the normal update by default. SetUpdate moves one to the fixed or late phase, and the independent flag makes a tween ignore the engine's time scale — which is how a pause menu keeps animating while the game is frozen.

angelscript 
Move(transform, target, 1.0f).SetUpdate(UpdateType::Fixed);
Move(transform, target, 1.0f).SetUpdate(true);                    // time-scale independent
Move(transform, target, 1.0f).SetUpdate(UpdateType::Late, true);

Move(transform, target, 1.0f).SetTimeScale(0.5f);   // this tween, at half speed
SetTimeScale(0.5f);                                 // every tween, at half speed

That is the whole feature set. For exact signatures, defaults and every shortcut in the package, carry on to the API reference.
