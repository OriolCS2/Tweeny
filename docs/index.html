A package for CometEngine

Tweeny

Animate anything over time — positions, rotations, scales, colours, alpha, UI, audio, or any value you can read and write. Written for CometEngine and AngelScript.

Tweeny is a tweening engine: you tell it where a value should end up and how long it should take, and it moves it there smoothly every frame. It handles the easing, the looping, the sequencing and the cleanup, so animation stops being something you hand-roll in Update and becomes one line. 

using namespace Tweeny;

Move(transform, Vector2(5.0f, 0.0f), 1.0f)
    .SetEase(Ease::OutBack)
    .SetLoops(-1, LoopType::Yoyo);

Install

Import the package into your CometEngine project. That is the whole setup — there is no manager prefab to place, no script to register and no initialisation call. Tweeny registers itself through a project setting, so the engine creates its runner at play start the moment the package is present.

Open Project Settings › TweenySettings to change the defaults: easing curve, loop type, auto-kill, auto-play, global time scale and logging.

The basics

Every tween is created by a function that takes what to animate, where it should end up and how long it should take. The call returns the tween, so settings chain onto it. 

// Slide to a position over half a second.
Move(transform, Vector2(3.0f, 0.0f), 0.5f);

// Grow, with an easing curve, and do it three times.
Scale(transform, 2.0f, 0.4f)
    .SetEase(Ease::InOutQuad)
    .SetLoops(3, LoopType::Yoyo);

// Fade a sprite out and do something when it lands.
Fade(renderer, 0.0f, 0.8f)
    .OnComplete(TweenCallback(this.OnFadedOut));

Shortcuts take their target as the first argument. AngelScript has no extension methods, so a shortcut cannot hang off the object as transform.Move(...) — it is Move(transform, ...) instead, a free function in the Tweeny namespace.

Features

Easing

Thirty-eight built-in curves. Back and Elastic overshoot, Bounce settles, Flash blinks. You can also pass your own function, or wrap any curve in a stop-motion sampler. 

Move(transform, target, 1.0f).SetEase(Ease::OutBounce);
Move(transform, target, 1.0f).SetEase(Ease::OutBack, 3.0f);          // stronger overshoot
Move(transform, target, 1.0f).SetEase(Ease::OutElastic, 1.5f, 0.4f); // amplitude, period
Move(transform, target, 1.0f).SetEase(EaseFunc(this.MyCurve));       // your own
Move(transform, target, 1.0f).SetEase(EaseFactory::StopMotion(8, Ease::Linear));

Loops and direction

Restart starts over each cycle, Yoyo alternates forwards and backwards, and Incremental keeps adding the change so the motion travels further each time. A loop count of -1 runs forever. 

MoveX(transform, 5.0f, 1.0f).SetLoops(-1, LoopType::Yoyo);
MoveX(transform, 5.0f, 1.0f).SetLoops(4, LoopType::Incremental);
MoveX(transform, 5.0f, 1.0f).SetDelay(0.5f).SetRelative(true);

Sequences

A sequence plays tweens on one timeline. Append puts one after the last, Join runs one alongside the last, Insert drops one at an exact time, and intervals and callbacks slot in anywhere. Sequences nest. 

TweenSequence@ intro = Sequence();
intro.Append(Move(transform, Vector2(0.0f, 3.0f), 0.5f));
intro.Join(Tint(renderer, red, 0.5f));          // at the same time as the move
intro.AppendInterval(0.2f);
intro.Append(Scale(transform, 1.5f, 0.3f));
intro.AppendCallback(TweenCallback(this.OnIntroDone));
intro.SetLoops(2, LoopType::Restart);

To animate two properties of the same object together you do not even need a sequence — two tweens on the same target simply coexist: 

Scale(transform, 1.5f, 0.4f);
Tint(renderer, red, 0.4f);

Punch, shake and jump

Impact effects that always end exactly where they started, so they can be fired on top of whatever else is happening. Shakes take a seed, so a shake can be replayed identically. 

PunchPosition(transform, Vector2(0.5f, 0.0f), 0.4f);
PunchScale(transform, Vector2(0.3f, 0.3f), 0.4f, 10, 1.0f);
ShakePosition(transform, 0.5f, 2.0f, 14);
ShakePosition(transform, 0.5f, 2.0f, 14, 90.0f, true, 4242);  // reproducible
Jump(transform, Vector2(8.0f, 0.0f), 3.0f, 2, 1.0f);

Paths

Move along a list of waypoints in straight lines or a smooth curve. The path is measured when the tween starts, so travel is at a constant speed rather than speeding up wherever the waypoints bunch together. 

array<Vector2> route = { Vector2(5, 3), Vector2(5, -1), Vector2(-5, -1) };

Path(transform, route, 4.0f, PathType::Linear).SetClosePath(true);
Path(transform, route, 4.0f, PathType::CatmullRom)
    .OnWaypointChange(TweenCallbackInt(this.OnWaypoint));

Callbacks and control

Nine lifecycle callbacks, and full playback control on any tween — including seeking to an arbitrary point on its timeline. 

TweenVector3@ t = Move(transform, target, 2.0f)
    .SetAutoKill(false)
    .OnStart(TweenCallback(this.OnStart))
    .OnStepComplete(TweenCallback(this.OnLoop))
    .OnComplete(TweenCallback(this.OnDone));

t.Pause();
t.Play();
t.Goto(1.2f);        // jump to 1.2 seconds in
t.Flip();            // reverse direction
t.Restart();
t.Complete(false);
t.Kill(false);

Finding tweens again

Tag tweens with an id, or find them by the object they animate, and drive them in bulk. 

MoveX(transform, 5.0f, 1.0f).SetId("intro");

Pause("intro");
Kill("intro");
Kill(transform);           // everything animating this transform
bool busy = IsTweening(transform);

PauseAll();
KillAll(true);             // true completes them first
SetTimeScale(0.25f);       // slow motion for every tween

Waiting in coroutines

Six yield instructions turn a coroutine into a readable cutscene script. A tween that gets killed releases the wait too, so a coroutine can never be stranded. 

void PlayIntro()
{
    Yield(WaitForCompletion(Move(transform, up, 0.6f).SetEase(Ease::OutBack)));
    Yield(WaitForSeconds(0.2f));
    Yield(WaitForCompletion(Tint(renderer, gold, 0.4f)));
    Yield(WaitForElapsedLoops(spinner, 3));
}

Animating your own values

Any pair of functions that read and write a value can be tweened. This is how you animate things Tweeny has never heard of — a health bar, a shader parameter, a score counter. 

float GetHealth() { return health; }
void SetHealth(float v) { health = v; }

To(FloatGetter(this.GetHealth), FloatSetter(this.SetHealth), 100.0f, 2.0f)
    .SetEase(Ease::OutQuint);

// Counting a score up, as whole numbers.
To(IntGetter(this.GetScore), IntSetter(this.SetScore), 1500, 1.5f);

// Typing text out, with scrambled characters filling the rest.
To(StringGetter(this.GetLabel), StringSetter(this.SetLabel), "READY", 1.0f)
    .SetScramble(ScrambleMode::Uppercase);

Tying a tween to an entity

A tween that outlives what it animates is the most common way tween code goes wrong. Link it, and it stops, restarts or dies along with the entity. A destroyed entity always kills the tween, whatever behaviour you pick. 

ITween@ t = Move(transform, target, 5.0f);
SetLink(t, entity, LinkBehaviour::PauseOnDisablePlayOnEnable);

No code at all

Add a TweenyAnimation component, pick what to animate and how, and press Play. It covers moves, scales, rotations, tints, fades, punches and shakes, with the same timing and looping options as the API.

The Tweeny Inspector

Tweeny › Tweeny Inspector in the main menu lists every live tween with its progress and state, and gives each one play, pause, rewind, complete and kill buttons. The preview button runs the tweens inside the editor without entering play mode, and puts every target back where it was when you stop.

How the API reads

Every shortcut is a free function in the Tweeny namespace that takes its target first, because AngelScript has no extension methods. Nothing carries a prefix — the namespace already keeps Tweeny::Move unambiguous. Everything after the shortcut is a chained setter that returns the tween, so a whole animation stays one statement.

Reads asWhat it does
Move(transform, v, t)Slides to a position
Scale(transform, s, t)Grows or shrinks
Rotate(transform, degrees, t)Turns by a scalar angle
Tint(renderer, c, t)Changes colour
Fade(renderer, a, t)Changes alpha only
Path(transform, ...)Follows a list of waypoints
Sequence()Builds a timeline of tweens
KillAll()Stops everything at once
Yield(WaitForCompletion(tween))Waits inside a coroutine
TweenyAnimationAnimates from the inspector, no code

Two names are worth calling out. Rotate takes a scalar angle rather than a quaternion, because CometEngine is 2D and that is also what makes RotateMode::FastBeyond360 expressible. And the colour shortcut is Tint, not Color, so it can never collide with Comet's own Color type in a file that imports both namespaces.

What is not here, and why

  • Object pooling. Pools exist to dodge a tracing garbage collector. AngelScript is reference counted, so a finished tween is released as soon as the last handle drops. A pool would buy nothing and bring its worst footgun: a recycled tween reporting itself alive while being a different animation entirely.
  • await-style asynchrony has no AngelScript equivalent. Nothing is lost: use OnComplete, or wait inside a coroutine.
  • Generic plugins. AngelScript has no script-side generics. Write a To with your own getter and setter instead — that is the extension point, and it is the same one every built-in shortcut is built on.
